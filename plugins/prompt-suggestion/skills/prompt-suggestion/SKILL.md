---
name: prompt-suggestion
description: Configure or inspect next-message suggestions using connected BB generation models.
---

Prompt Suggestion (formerly Autosay) prepares a source-linked task state and an editable next message that advances the owner goal after an eligible completed turn. It uses BB's shared experimental AI-generation service, independently of the working agent's provider. It starts disabled; choose a model in the plugin's Suggestion model picker, then enable it. Existing provider authentication stays in the provider adapter; this plugin has no API URL or key setting.

Use `bb prompt-suggestion models` for supported model IDs and their connection identity, `bb prompt-suggestion status` for configured selection and enabled state, and `bb prompt-suggestion diagnostics` for session-only counters and last latency. Configured means a model ID is saved; an unavailable saved model fails without switching to another model. Refresh the picker after connecting a provider or changing the primary machine.

Native settings control instructions, context character limit, timeout, output token limit, hourly request limit and allowed project IDs. The configured provider receives bounded conversation text, compact task state with exact source references, and the complete owner BIBLE. Core supplies BIBLE bytes and their revision through `experimental_userInstructions.read()`; missing, empty or unreadable instructions prevent generation. The context limit applies to conversation selection, not BIBLE truncation. Output token limit 0 uses the provider default; a positive value requires advertised provider support and otherwise fails before dispatch. No automatic retries or fallback models are selected by Prompt Suggestion. Admission is deduplicated for one hour in the current plugin process, including none and error results; clearing cached data or resetting settings does not erase that history. Restart clears process-local history. Remote usage/cost follows the selected provider; timeout ends local waiting but cannot guarantee remote billing stops.

`bb prompt-suggestion suggest --thread <id>` generates once for an idle eligible thread and prints JSON; it does not insert or send. Optional `--request <UUID> --token <UUID>` creates a cancellable request; cancel using `bb prompt-suggestion cancel --request <UUID> --token <UUID>`. These are transient cancellation identifiers, not provider secrets. Cancellation only stops a job when that manual request is its sole owner; an RPC disconnect detaches its waiter and does not cancel shared background work.

A foreground visit tracks the thread even while its agent is active. Tracking lasts ten minutes, renews on a new completed turn in the foreground, and is bounded to eight threads; background preparation is separately configurable. Active threads prepare context without inference; successful completed root turns can enter the one-at-a-time generation queue. Lifecycle events and tagged RPC invalidation drive updates without polling or keepalive. `bb prompt-suggestion track --thread <id>` establishes the same bounded interest, `state --thread <id>` reads the current checked job, `inspect --thread <id>` explicitly returns task state and source messages, and `clear-cache --thread <id>` removes prepared data without resetting admission. Diagnostics never return task content.

Displaying a candidate requires a focused visible empty composer, the matching completed root turn, no queued message or pending command/permission approval, and no upload/voice operation. Open conversation questions do not suppress suggestions or require answering first. Typing, focus/context/settings changes invalidate local results. Unmount detaches the local client; background work can finish and be reused on return. Dismissed jobs do not repeatedly reappear in the same mounted controller. The candidate replaces the placeholder: Tab accepts editable text; plain Enter or native Send accepts and submits once through the usual host path. Typing/Escape dismisses it. Unsupported custom composers remain off.

Reasoning effort and Processing speed are explicit native settings. Provider default leaves the corresponding option unset. The model picker lists supported values; unsupported choices fail before generation and are never silently substituted. Fast can use a higher quota or price. The general agent model picker does not set these generator options.

The complete BIBLE comes from core; task guidance lives in src/instructions.ts, with an optional native setting supplement. Task facts link to exact source messages and revisions, and distinguish accepted criteria, proposals, reported progress and visible evidence. Context clearing resets earlier task memory; bounded history does not imply complete context. No transcript/suggestion corpus or model content log is added. Existing BB drafts and sent history keep their ordinary retention. Dataset export and background sending are outside this plugin.

When upgrading Autosay, inspect its non-secret settings, disable the old plugin before enabling Prompt Suggestion, and choose a native model explicitly. Direct API configuration does not map automatically to a BB connection. Do not silently migrate credentials or leave both composer controllers active.

While a request is pending, the composer shows Preparing suggestion and a spinner. None/cancellation restores the normal placeholder; failure/timeout exposes a small pressable error disclosure. Pending text cannot be submitted. Settings show enabled state, selected model, reasoning and requested processing speed. CLI status/diagnostics remain available for inspection.

This implementation is local work only. Verification does not authorize publishing, deployment, an installed pilot or a release.

Job state exposes server preparation, queue, model and validation durations, total server duration, actual model/tier, finish reason and output budget. A truncated response remains `output_truncated`; it is not retried automatically. Diagnostics include the last browser-observed-ready-to-attachment duration and its job ID. Browser and server clocks are never subtracted; this measurement excludes transport and does not claim completion-to-display latency. Missing attachment evidence is null.


## Separate suggestion and memory roles

Foreground generation returns only `{kind: "suggestion", text}` (at most 600 Unicode code points) or `{kind: "none"}`. CLI/RPC suggestion responses have no task state; `inspect --thread <id>` remains the derived memory surface. After a validated completed snapshot settles, an independent memory lane may refresh source-linked TaskState. Streaming snapshots do not trigger memory inference. Both roles receive the same selected model, effort, tier, full owner BIBLE and current messages; only the role contract and output cap differ. `outputTokenLimit` controls suggestions; `memoryOutputTokenLimit` controls memory (both default to 0, the provider default; positive caps require support).

Both roles share the rolling-hour request budget, preserved across cache clear/reset. Memory reserves the final available request for foreground work, never runs with a limit of 1, and yields by cancellation to new foreground demand. Failed or cancelled admitted memory snapshots are not retried during that window. Memory failure does not remove a suggestion. Diagnostics expose separate memory counters; job latency and usage remain foreground-only. This is local scheduling priority, not a global SDK slot reservation. Shared slots stay occupied until provider cleanup settles, so foreground work can report `busy` during cancellation or other callers' activity; that admitted snapshot is not silently retried.

The synthetic pilot accepts `--role suggestion` (default) or `--role memory`; each uses its matching production prompt and output schema. Historical full-state-plus-suggestion artifacts are not current-run output.
